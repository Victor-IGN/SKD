# Архитектура информационной системы контроля исполнения договоров

## 1. Общая архитектура системы
Разрабатываемая система построена по трехуровневой клиент-серверной архитектуре:
* **Уровень представления (Клиент):** Веб-интерфейс, доступный через браузер. Реализуется с использованием HTML5, CSS3 и JavaScript (фреймворк React).
* **Уровень бизнес-логики (Сервер):** REST API, обрабатывающее запросы клиента, проверяющее права доступа и выполняющее бизнес-правила (например, расчет статуса договора). Реализуется на Python (фреймворк FastAPI).
* **Уровень хранения данных (БД):** Реляционная база данных PostgreSQL для надежного хранения структурированной информации о договорах, контрагентах и пользователях.

## 2. Взаимодействие компонентов
1. Пользователь (юрист или менеджер) авторизуется в веб-интерфейсе.
2. При создании нового договора клиент отправляет HTTP-запрос (JSON) к серверу API.
3. Сервер валидирует данные, применяет бизнес-логику и сохраняет запись в базу данных.
4. Фоновый процесс (Celery) раз в сутки проверяет базу данных на предмет приближающихся дедлайнов по договорам и инициирует отправку email-уведомлений.

## 3. Безопасность
* Использование протокола HTTPS для шифрования трафика.
* Аутентификация на основе JWT-токенов (JSON Web Tokens).
* Ролевая модель доступа (RBAC) на уровне API (разграничение прав администраторов, юристов и менеджеров).
